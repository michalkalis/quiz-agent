## Agent Brief — 2026-08-14

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** One canonical ratings store in quiz-pack-api Postgres + a served multi-rater blind-rating web page, replacing the local single-user rating.html flow.

**Current behavior:**
Rating pages are static files generated per run into `docs/testing/runs/<run>/` (blinded ids `q01…` + separate `mapping.json`); ratings live only in the rater's browser localStorage and reach the repo via manual JSON export. Single rater only, no server persistence, no per-person attribution.

**Desired behavior:**
- **Store:** two new tables in quiz-pack-api Postgres (Alembic, additive):
  - *rating batches* — batch id (unguessable token), title, created date, the blinded question list (id, question text, answer, safe metadata) and the server-side-only blind mapping (arm, original question UUID, model/prompt provenance). The page must never receive arm/mapping fields — blinding is preserved server-side.
  - *ratings* — append-only rows: batch id, blinded question id, original question id (nullable), question text snapshot, rater name, raw score, scale bounds (supports historical 1–5 and current 1–10), optional text reason, source (`web` / `in-app` / `backfill:<round>`), rated-at timestamp, free JSON extras. Re-rating the same question by the same rater updates that rater's row (last write wins), history preserved via appended rows or an updated-at — pick one and document it.
- **Batch creation:** a CLI script (evolution of `build_page.py`, reusing its interleave/seeded-shuffle/`--dedupe-by-fact` logic) takes arm JSONs and registers a batch via an admin-key API call instead of writing static files. Prints the shareable per-rater URLs.
- **Rating web:** `GET /web/rate/{batch_token}?rater=<name>` serves the rating page (adapt `scripts/rating_page/template.html`: keep the 1–10 meter, reason field, localStorage autosave and the rescue panel as offline backup). New: each score/reason change is persisted to the server (debounced POST), the page loads this rater's existing ratings on open (resume across devices), shows progress (rated/total). Missing `rater` param → simple name prompt that rewrites the URL. No admin gate on this route — the batch token is the capability; the existing `/web` admin pages stay admin-gated.
- **Ingest API:** POST endpoint accepting a rating for (a) web raters — authorized by valid batch token, and (b) the iOS app (#155) — authorized by the owner's bearer JWT (precedent: order retry accepts it) with an explicit question UUID instead of a batch/blinded id.
- **Export:** a CLI/script producing the canonical dataset as JSONL (one row per rating, raw + normalized-to-10 score, source round, date, rater, question identity) — the input for D21 correlation analysis and the P1 frozen eval set. #156 backfills history into the same store so this export covers everything.

**Key interfaces / call paths:**
- `app/web/routes.py` + `app/web/templates/` — precedent for served pages; new rate route must NOT inherit `require_admin`.
- `app/api/v1/` router registration in `app/main.py` — new ratings router alongside `orders`/`appstore`.
- `app/db/models/` + Alembic `versions/` — new models; boot-time head check (`migration_check.py`) means migrate-before-deploy.
- `scripts/rating_page/build_page.py` — blinding/dedupe logic to reuse; the static-file mode may remain for offline fallback.
- Bearer JWT validation as done for the order-retry path (#146).

**Acceptance:** see the top-level `## Acceptance` block.

**Out of scope:**
- iOS UI (#155) and historical backfill (#156).
- Any generation prompt/model/threshold change; any reading of ratings by the generation pipeline (later, per D21 outcomes).
- Delivery-flow / product packaging changes; auth system, accounts, passwords.
- Deleting `build_page.py` static mode or old run dirs.

**Suggested feedback loop:**
`cd apps/quiz-pack-api && pytest tests/ -v` (new tests for batch registration, token auth boundaries, rating upsert, export); then a local end-to-end: register a 3-question batch via CLI against `uvicorn :8003`, rate it in a browser as two different raters, assert both attributions in the export JSONL.
